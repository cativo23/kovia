  <files>
    frontend/app/plugins/api.ts, frontend/app/composables/useApi.ts,

  </files>
  <action>
    1. Create API client plugin (`frontend/app/plugins/api.ts`):
       - Uses `$fetch` from Nuxt (ofetch) configured with baseURL from runtimeConfig.public.apiUrl
       - Attaches Authorization Bearer header from auth store's access token
       - On 401 response: attempts silent refresh via /auth/refresh (credentials: 'include' for cookie), retries original request
       - If refresh also fails: clear auth state, redirect to /login
       - Export as `$api` available via `useNuxtApp()`

    2. Create `useApi` composable (`frontend/app/composables/useApi.ts`):
       - Wrapper around the $api plugin for convenient use in components
       - Typed methods: get<T>, post<T>, put<T>, delete<T>
       - Handles loading state and error state

    3. Create Pinia auth store (`frontend/app/stores/auth.ts`):
       - State: user (User | null), accessToken (string | null), isInitialized (boolean)
       - Getters: isAuthenticated, isAdmin, isOrgAdmin, userRole
       - Actions:
         - `register(dto)`: POST /auth/register, does NOT auto-login (user must verify email)
         - `login(email, password)`: POST /auth/login (credentials: 'include'), stores access token in memory + user data
         - `loginWithGoogle()`: redirects to API_URL/auth/google (full page redirect)
         - `handleOAuthCallback(token)`: stores access token from query param, fetches user profile via GET /auth/me
         - `verifyEmail(token)`: POST /auth/verify-email, stores returned tokens
         - `forgotPassword(email)`: POST /auth/forgot-password
         - `resetPassword(token, password)`: POST /auth/reset-password, stores returned tokens
         - `refreshToken()`: POST /auth/refresh (credentials: 'include'), updates access token
         - `logout()`: POST /auth/logout (credentials: 'include'), clear state, redirect to /login
         - `initialize()`: try refreshToken silently on app load (restores session after page refresh per AUTH-04)
       - Access token stored ONLY in memory (Pinia state) -- never localStorage (per research anti-patterns)
       - Refresh token managed as httpOnly cookie by backend -- frontend never reads it directly

    4. Create `useAuth` composable:
       - Convenience wrapper over auth store for template use
       - Returns reactive refs: user, isAuthenticated, isAdmin

    5. Create route middleware:
       - `auth.ts` (named middleware): if not authenticated AND not initialized, try initialize(); if still not authenticated, redirect to /login
       - `guest.ts` (named middleware): if authenticated, redirect to / (prevents logged-in users from seeing login/register)
       - `admin.ts` (named middleware): if not admin role, redirect to / with error toast

    6. Create layouts:
       - `auth.vue`: Centered card layout for login/register/verify/reset pages. Logo at top, card in center, minimal footer. Uses Nuxt UI components.
       - `default.vue`: Standard app layout with top navbar showing: logo, nav links, user menu dropdown (profile, logout) or login/register buttons. Responsive.
       - `admin.vue`: Admin layout with left sidebar nav (Dashboard, Organizaciones, Usuarios, Invitaciones) and main content area. Shows "Panel de Administracion" header. Per CONTEXT.md: separate /admin route with its own layout.

    7. Update `frontend/i18n/locales/es-SV.json` with comprehensive translations for all auth flows, layouts, common UI elements, and error messages. Include:
       - auth.* (login, register, verify, reset, errors, validation messages)
       - common.* (loading, save, cancel, delete, confirm, back, error, success)
       - nav.* (home, login, register, logout, profile, admin)
       - admin.* (dashboard, orgs, users, invites, stats)
       - org.* (profile fields, status labels)
       - validation.* (required, email, minLength, maxLength, passwordMismatch)
       All in Salvadoran Spanish (vos form where applicable: "verifico", "ingreso", "registro").
  </action>
