    1. Create `frontend/playwright.config.ts`:
       - Base URL: http://localhost:3001
       - Use Chromium only for speed in dev (can add Firefox/WebKit later)
       - Timeout: 30 seconds per test
       - Retries: 0 in CI, 1 in local
       - Output directory: frontend/test-results
       - Web server: NOT needed (Docker Compose already runs the app)
       - Reporter: list (for terminal output)

    2. Create `frontend/tests/e2e/auth.spec.ts` with Playwright tests:

       **Register flow:**
       - Navigate to /register
       - Verify page is in Spanish (check for "Crear cuenta" heading)
       - Fill form: firstName, lastName, email (unique per test run), password, confirmPassword
       - Submit form
       - Verify "Revisa tu correo" success message appears

       **Email verification flow:**
       - After register, fetch the verification email from Mailpit API: `GET http://localhost:8025/api/v1/messages` (Mailpit exposes a REST API)
       - Extract the verification token/link from the email body
       - Navigate to the verification URL
       - Verify auto-login: user is redirected to home page and sees welcome message

       **Login flow:**
       - Navigate to /login
       - Verify page is in Spanish (check for "Iniciar sesion")
       - Fill email + password
       - Submit
       - Verify redirect to home page with authenticated state

       **Session persist flow:**
       - After login, reload the page (page.reload())
       - Verify user is still authenticated (welcome message still visible, no redirect to /login)
       - This confirms silent token refresh via httpOnly cookie works

       **Password reset flow:**
       - Navigate to /forgot-password
       - Enter registered email
       - Verify confirmation message
       - Fetch reset email from Mailpit API
       - Navigate to reset link
       - Fill new password form
       - Verify auto-login after reset

    3. Ensure test uses Mailpit REST API (http://localhost:8025/api/v1/) to:
       - Fetch latest messages: GET /api/v1/messages
       - Search by recipient: GET /api/v1/search?query=to:{email}
       - Extract links from HTML body using regex

    NOTE: Tests require all Docker services running. Run via: `docker compose exec web npx playwright test --reporter=list`
    Playwright and playwright-core should already be installed from Plan 01-01 frontend scaffolding.
    If Playwright browsers are not installed in the container, run: `docker compose exec web npx playwright install chromium`

<task type="auto">
  <name>Task 2: Backend auth E2E tests against live API + database</name>
  <files>
    backend/test/e2e/auth.e2e.spec.ts
  </files>
  <action>
    1. Create `backend/test/e2e/auth.e2e.spec.ts` using Vitest (configured in backend/vitest.config.e2e.ts from Plan 01-01):

       **Test setup:**
       - Use NestJS testing utilities (Test.createTestingModule) to create a full app instance with all real modules (not mocked)
       - OR use supertest/fetch against the running API at http://localhost:3000 (simpler, tests the real deployment)
       - Preferred approach: HTTP requests against running API (tests the full stack including middleware, guards, DB)
       - Use a unique email prefix per test run to avoid collisions

       **Register endpoint E2E:**
       - POST /auth/register with valid data -> 201, user created in DB
       - POST /auth/register with duplicate email -> 409 Conflict
       - POST /auth/register with invalid data (missing fields) -> 400

       **Verify email endpoint E2E:**
       - Fetch verification token from Mailpit API after register
       - POST /auth/verify-email with valid token -> 200 + tokens returned
       - POST /auth/verify-email with expired/invalid token -> 401

       **Login endpoint E2E:**
       - POST /auth/login with valid credentials (after verification) -> 200 + accessToken in body + Set-Cookie header with refresh token
       - POST /auth/login with wrong password -> 401
       - POST /auth/login with unverified email -> 403

       **Refresh endpoint E2E:**
       - POST /auth/refresh with valid cookie -> 200 + new accessToken
       - POST /auth/refresh without cookie -> 401

       **Password reset E2E:**
       - POST /auth/forgot-password with valid email -> 200
       - Fetch reset token from Mailpit
       - POST /auth/reset-password with valid token + new password -> 200 + tokens

       **Session persistence E2E:**
       - Login, get refresh cookie
       - Use refresh cookie to get new access token
       - Use new access token to call GET /auth/me -> 200 + user data

    2. Each test should clean up after itself or use unique emails to avoid test pollution.

    3. Run via: `docker compose exec api npx vitest run --config vitest.config.e2e.ts --reporter=verbose`
  </action>
