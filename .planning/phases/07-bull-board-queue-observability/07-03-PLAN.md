<objective>
Add a "Colas de Jobs" link to the admin sidebar that navigates the browser directly to the backend Bull Board UI at /admin/queues, appending the Pinia access token as a query parameter so BullBoardAuthMiddleware can authenticate the request.

Purpose: Without this link, the platform admin has no discoverable path to the Bull Board UI. The token-in-URL approach (RESEARCH.md Option B) is intentional for this internal-only tool — browser navigation cannot send Bearer headers, and the access token lives in Pinia memory (not a cookie).

Output: Admin sidebar shows "Colas de Jobs" with activity icon; clicking it opens Bull Board in a new tab with the admin's JWT pre-authenticated.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Nuxt frontend → backend /admin/queues | Admin navigates from same-origin Nuxt app to different-origin backend URL |
| Pinia memory → URL query string | Access token crosses from JS heap to URL (browser history, server access logs) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-08 | Information Disclosure | ?token= in admin sidebar href | accept | Internal tool only; access token is short-lived (15 min); URL is only visible to logged-in PLATFORM_ADMIN; risk is low; documented with inline comment in template |
| T-7-09 | Information Disclosure | target="_blank" link | mitigate | rel="noopener noreferrer" added to prevent the opened page from accessing window.opener — standard practice for all external links |
| T-7-10 | Spoofing | Admin panel accessible to non-admin users | accept | Admin layout is only rendered on /admin/* routes; Nuxt route guard + backend PLATFORM_ADMIN check protect the parent page; the Bull Board link is only visible to users who already cleared those guards |
</threat_model>
