## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fetchApplicationContext() Prisma query → email dispatch | adopter email address read from DB, passed directly to Mailable — no user-supplied input |
| verifyEmail() JWT → WelcomeMail dispatch | email address comes from verified JWT payload sub → DB lookup; no injection risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Spoofing | WelcomeMail trigger in verifyEmail | accept | Trigger fires only after `jwtService.verifyAsync()` succeeds with the email-verification token type. Token is issued server-side. No spoofing vector. |
| T-06-03-02 | Denial of Service | ApplicationSubmittedMail with invalid adopterEmail | mitigate | If adopterEmail is empty string (context fetch returns ''), mailerService.sendMail() will fail gracefully and BullMQ retry handles it. Worker `onFailed` logs the failure. No crash. |
| T-06-03-03 | Repudiation | Email sent without DB record | accept | BullMQ job is ephemeral (not durable). At current scale, convention (D-11) + retry is sufficient. Transactional outbox deferred per D-11 rationale. |
</threat_model>
