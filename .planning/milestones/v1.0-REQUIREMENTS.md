# Requirements Archive: Kovia v1.0

**Archived:** 2026-04-21 at milestone close
**Status:** ✅ SHIPPED — all v1 requirements delivered (AUTH-05 moved to v2)
**Core Value:** The right pets get matched with the right people — every adoption decision is informed by structured data, scoring, and applicant history.

---

## v1 Requirements — Final Status

### Authentication

- [x] **AUTH-01**: User can sign up with email and password — ✓ Phase 1
- [x] **AUTH-02**: User receives email verification after signup — ✓ Phase 1
- [x] **AUTH-03**: User can reset password via email link — ✓ Phase 1
- [x] **AUTH-04**: User session persists across browser refresh (JWT + refresh tokens) — ✓ Phase 1
- [ ] **AUTH-05**: User can sign in with OAuth (Google) — **moved to v2** (route partially wired; not implemented in v1)

### Organization Management

- [x] **ORG-01**: Organization has a profile with name, description, logo, and contact info — ✓ Phase 1
- [x] **ORG-02**: Platform admin can approve or reject organization registration requests — ✓ Phase 1
- [x] **ORG-03**: Each organization has a single admin who manages all org data — ✓ Phase 1
- [x] **ORG-04**: All organization data is isolated via multi-tenant RLS policies — ✓ Phase 1

### Animal Management

- [x] **ANIM-01**: Rescue staff can create, edit, and delete animal profiles — ✓ Phase 2
- [x] **ANIM-02**: Animal profile includes species, breed, age, size, energy level, and compatibility attributes — ✓ Phase 2
- [x] **ANIM-03**: Rescue staff can upload multiple photos per animal (cloud storage with presigned URLs) — ✓ Phase 2
- [x] **ANIM-04**: Animal has a status lifecycle: available → in process → adopted — ✓ Phase 2

### Adoption Workflow

- [x] **ADOP-01**: Adopter can submit a structured multi-step application for a specific animal — ✓ Phase 3
- [x] **ADOP-02**: Application form has mandatory fields (personal info, housing) and optional fields — ✓ Phase 3
- [x] **ADOP-03**: Application requires environment photo uploads — ✓ Phase 3
- [x] **ADOP-04**: Application form state persists in localStorage (survives connection drops and page refresh) — ✓ Phase 3
- [x] **ADOP-05**: Application status follows a state machine: submitted → reviewing → approved/rejected/follow-up → adopted/withdrawn — ✓ Phase 3
- [x] **ADOP-06**: Rescue staff can view and filter/sort the application queue per animal — ✓ Phase 3

### Scoring & Screening

- [x] **SCOR-01**: System generates a rule-based score (0-100) for each submitted application — ✓ Phase 4
- [x] **SCOR-02**: Score produces a risk level classification: low, medium, or high — ✓ Phase 4
- [x] **SCOR-03**: Score breakdown by rule is visible to rescue staff (transparency) — ✓ Phase 4
- [x] **SCOR-04**: System flags red flags: incomplete info, inconsistencies, past animal returns — ✓ Phase 4
- [x] **SCOR-05**: Scoring rules include: housing situation, pet experience, environment photos, lifestyle fit, compatibility, completeness, and red flags — ✓ Phase 4
- [x] **SCOR-06**: Scores are advisory — staff can override and make final decisions regardless of score — ✓ Phase 4

### Staff Dashboard

- [x] **DASH-01**: Rescue staff can view and manage all animals for their organization — ✓ Phase 2
- [x] **DASH-02**: Rescue staff can view all applications per animal with scores and risk levels — ✓ Phase 4
- [x] **DASH-03**: Rescue staff can update application status from the dashboard — ✓ Phase 4
- [x] **DASH-04**: Rescue staff can add internal notes to any application (visible only within their org) — ✓ Phase 4
- [x] **DASH-05**: Rescue staff can view an adopter's past applications and adoption outcomes — ✓ Phase 4

### Public Listings

- [x] **LIST-01**: Anyone can browse available animals without creating an account — ✓ Phase 2
- [x] **LIST-02**: Public listings can be filtered by species, size, age, and organization — ✓ Phase 2
- [x] **LIST-03**: Public listing pages are server-side rendered for SEO — ✓ Phase 2
- [x] **LIST-04**: Animal detail pages include Open Graph meta tags for social media sharing — ✓ Phase 2
- [x] **LIST-05**: Each organization has a public landing page showing their available animals — ✓ Phase 2

### Notifications & Automation

- [x] **NOTF-01**: Adopter receives in-app notifications when their application status changes — ✓ Phase 5
- [x] **NOTF-02**: System fires webhook events to n8n when key actions occur — ✓ Phase 5
- [x] **NOTF-03**: Webhook delivery uses outbox pattern with idempotency keys and exponential backoff retry — ✓ Phase 5

### Applicant History

- [x] **HIST-01**: System stores all past applications per adopter across organizations — ✓ Phase 4
- [x] **HIST-02**: Adoption outcomes (successful, returned, withdrawn) are tracked per application — ✓ Phase 4
- [x] **HIST-03**: Past return flags are visible to rescue staff reviewing new applications from the same adopter — ✓ Phase 4

### Infrastructure

- [x] **INFR-01**: Application is containerized with Docker and Docker Compose for local development — ✓ Phase 1
- [x] **INFR-02**: UI is Spanish-first (es-SV locale) with i18n infrastructure for future languages — ✓ Phase 1
- [x] **INFR-03**: Multi-tenant data isolation enforced at database level via PostgreSQL Row-Level Security — ✓ Phase 1
