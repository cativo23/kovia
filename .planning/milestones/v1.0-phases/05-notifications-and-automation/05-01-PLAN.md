Create WebhookProcessor extending WorkerHost:

```ts
@Processor('webhook')
export class WebhookProcessor extends WorkerHost {
  constructor(private prisma: PrismaService, private http: HttpService | native fetch) {
    super();
  }

  async process(job: Job<{ outboxId: string }>) {
    // 1. Fetch outbox entry using publicPrisma.$transaction with admin bypass
    // 2. If not found or already DELIVERED, return
    // 3. POST to N8N_WEBHOOK_URL with:
    //    - Body: outbox.payload
    //    - Headers: Content-Type: application/json, X-Idempotency-Key: outbox.idempotencyKey
    //    - Timeout: 10s
    // 4. On 2xx success: update status to DELIVERED, set deliveredAt
    // 5. On 5xx or network error: increment attempts, update nextAttemptAt, throw error (triggers retry)
    // 6. On 4xx (non-retryable): update status to FAILED, set lastError
    // 7. On max attempts reached: update status to FAILED, set lastError
  }
}
```

Key behaviors:
- Uses publicPrisma.$transaction with set_config('app.is_admin', 'true', true) (no CLS context in workers)
- Distinguishes retryable (5xx, timeout, network) from non-retryable (4xx) errors
- Updates outbox status appropriately after each attempt
- Throws on retryable errors to trigger BullMQ retry
- Logs errors for observability
</action>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| WebhookOutbox entries visible to unauthorized users | Medium | RLS disabled but API only accessible via admin endpoints; no public endpoint exposes outbox |
| Notification privacy leak (user sees other user's notifications) | High | RLS policy: users can only SELECT their own notifications; controller verifies ownership |
| Webhook replay attack (duplicate delivery to n8n) | Medium | IdempotencyKey in outbox ensures single enqueue; X-Idempotency-Key header sent to n8n |
| BullMQ job loss on Redis restart | Low | Redis persistence (RDB/AOF) configured in docker-compose; outbox table provides durable source for re-enqueue |
| Notification spoofing (malicious actor creates fake notifications) | Medium | Only EventsService creates notifications; no public API allows direct notification creation |
| Webhook endpoint exfiltration (N8N_WEBHOOK_URL intercepted) | Low | URL sent server-to-server only; no client-side exposure |
| Denial of service via notification spam | Medium | Rate limiting on application/note creation APIs (existing); notification creation is bounded by these limits |
</threat_model>
