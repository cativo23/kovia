<objective>
Fix UAT Gap 3 (MINOR, Tests 2 and 8): the animal card on `/animales` and on `/org/:slug` renders raw i18n keys like `animals.form.size.large` instead of localized labels like "Grande". Nuxt logs: `[intlify] Not found 'animals.form.size.large' key in 'es' locale messages`.

Investigation summary (grepped before writing this plan):
- Keys exist in `frontend/i18n/locales/es-SV.json` under `animals.form.sizeOptions.{small,medium,large,extraLarge}` (line 282 of the JSON) with Spanish values `Pequeno / Mediano / Grande / Extra grande`.
- `AnimalForm.vue` uses the CORRECT path `animals.form.sizeOptions.<key>` (lines 268-271).
- `pages/animales/[id]/index.vue` uses the CORRECT path `animals.form.sizeOptions.${sizeKey(animal.size)}` (line 60).
- `AnimalCard.vue` uses the WRONG path `animals.form.size.${sizeKey(animal.size)}` in TWO places:
  - line 50 (grid mode)
  - line 115 (list mode)
- The `sizeKey()` function at `AnimalCard.vue:178-186` correctly maps `EXTRA_LARGE -> 'extraLarge'` etc., matching the JSON's `extraLarge` key. So the fix is purely the key path prefix.

Fix: change both occurrences in `AnimalCard.vue` from `animals.form.size.` to `animals.form.sizeOptions.`. No other file needs to change. No new keys to add.

Purpose: Localized labels are table-stakes for a Spanish-first product; a raw key leak is a visible bug on a public-facing listing.
Output: `/animales` and `/org/:slug` render "Pequeno/Mediano/Grande/Extra grande" for animal size, and no intlify warnings for `animals.form.size.*` appear in the Nuxt log.
</objective>

function sizeKey(size: string): string {
  const map: Record<string, string> = {
    SMALL: 'small',
    MEDIUM: 'medium',
    LARGE: 'large',
    EXTRA_LARGE: 'extraLarge',
  }
  return map[size] || size.toLowerCase()
}
