## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between badge and label |
| sm | 8px | Compact element spacing, gap between stacked notes |
| md | 16px | Default element spacing within UCard body |
| lg | 24px | Gap between right-column UCards, section padding |
| xl | 32px | Layout gaps between left/right column sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used in this phase's dense dashboard views) |

Exceptions:
- Touch targets for transition buttons: minimum 44px height (UButton block layout already satisfies this)
- Score number display: 48px font-size equivalent for the bold numeric score (display typography, not spacing)

> Source: Established 8-point scale from prior phases (org layout.vue uses p-4, p-6, gap-3, gap-6 consistently).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label / Meta | 12px (text-xs) | 400 (regular) | 1.4 |
| Section heading | 16px (text-base) | 700 (bold) | 1.2 |
| Score display | 28px (text-3xl) | 700 (bold) | 1.0 |

> Source: Existing `[id].vue` uses `text-sm` for body, `font-bold text-base` for card headers, `text-2xl font-bold` for page headings. Score display (D-14) requires a distinct display size — 28px at bold weight is prescribed here.

Notes:
- 4 sizes declared (12, 14, 16, 28). Exactly 2 weights in use: 400 (regular) and 700 (bold).
- Section headings use `font-bold` (700), not `font-semibold`. All strong-emphasis elements share weight 700.
- "hace 2 horas" timestamps in notes: text-xs at 400 weight, color neutral-400.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-white` / `bg-gray-50` (dark: `bg-gray-950`) | Page background (main content area), UCard surfaces |
| Secondary (30%) | `bg-gray-50` / sidebar `bg-white dark:bg-gray-900` | Right decision column, sidebar nav, table zebra rows |
| Accent (10%) | `primary` = green (Nuxt UI semantic color) | Active nav item highlight, primary CTA buttons, score number text when bajo_riesgo |
| Destructive | `error` = red (Nuxt UI semantic color) | RECHAZAR transition button, hard red flag UAlert, DEVUELTA badge |

Accent reserved for:
1. Active sidebar nav item (`bg-primary/10 text-primary`)
2. Primary CTA button ("Agregar nota", "Re-puntuar solicitud")
3. `bajo_riesgo` risk badge background
4. Score number color when risk is `bajo_riesgo`

Risk level badge color mapping (UBadge color prop):
- `bajo_riesgo` (80-100): `success` (green)
- `riesgo_moderado` (60-79): `info` (blue)
- `requiere_revision` (40-59): `warning` (yellow)
- `alto_riesgo` (0-39): `error` (red)

Red flag UAlert severity colors:
- HARD red flags: `color="error"` UAlert — always rendered above score panel when present
- MEDIUM red flags: `color="warning"` UAlert — always rendered above score panel when present
- SOFT flag (activity mismatch): `color="neutral"` inline note inside score breakdown, not a blocking alert

Score "Pendiente" placeholder: `text-gray-400 italic` — same treatment as existing `—` placeholder in queue table.

> Source: .nuxt/app.config.mjs color config, org.vue layout, ApplicationStatusBadge.vue color pattern, CONTEXT.md D-15, D-16.

## Layout — Application Detail Page (`[id].vue`)

Right column card order (top to bottom):
1. **RedFlagsAlert** — rendered only when `redFlags.length > 0`; hard flags above medium flags; absent when score is null and no flags computed yet
2. **ScorePanel** — status, score number, risk badge; UCollapsible "Ver desglose" with 5 category rows
3. **Status panel** (existing) — current status badge + transition buttons
4. **ApplicantHistorySummary** — totals + link to adopter profile
5. **InternalNotes** — note list + add-note form
6. **Animal summary** (existing) — unchanged

**Primary focal point:** Score number (28px bold) in ScorePanel — largest typographic element in the right column. Draws staff eye immediately on page load. All other right-column elements are subordinate to this number in visual hierarchy.

> Source: CONTEXT.md D-14, D-15, D-17, D-18, D-19; existing [id].vue right column order.

## Interaction States

### ScorePanel

| State | Visual |
|-------|--------|
| Score null (job pending) | "Pendiente de evaluacion" in text-sm text-gray-400 italic; no badge; no breakdown toggle |
| Score computed, shadow mode ON | Score hidden from staff — ScorePanel not rendered in staff UI (config flag `SCORING_DISPLAY_ENABLED`) |
| Score computed, shadow mode OFF | Score number (28px bold), RiskBadge, UCollapsible breakdown |
| Breakdown expanded | 5 category rows: "Vivienda y ambiente — 18/25 pts", etc., each row text-sm |
| Re-score loading | UButton "Re-puntuar solicitud" shows loading spinner; score area shows "Recalculando..." text-gray-400 italic |

### InternalNotes

| State | Visual |
|-------|--------|
| Empty notes | Empty state copy centered in card body |
| Notes present | Chronological list, newest at top. Each note: body text (text-sm), then "Nombre Autor · hace 2 horas" (text-xs text-neutral-400) |
| Adding note | UTextarea active + "Agregar nota" UButton (primary color); button disabled if textarea is empty |
| Save loading | "Agregar nota" button shows loading state |
| Save error | UToast error in red |

### Queue table score column

| State | Visual |
|-------|--------|
| Score null | "—" in text-gray-400 italic |
| Score present | Numeric score + RiskBadge inline, e.g., "72 [Riesgo moderado]" |
| Column sortable | Default sort: descending by score (nulls last) |

### DEVUELTA transition

| State | Visual |
|-------|--------|
| Transition button | "Registrar devolucion" UButton color="error" in transition list for ADOPTADA status |
| Confirmation modal | Same UModal pattern as existing transitions; body: "Esta accion registrara que el animal fue devuelto. ¿Continuar?" |
| Post-transition | ApplicationStatusBadge updates to DEVUELTA (color error, label "Devuelta") |

## Accessibility Notes

- Red flag UAlert must include `role="alert"` (Nuxt UI UAlert already sets this)
- Score breakdown UCollapsible button must have aria-expanded attribute (Nuxt UI UCollapsible handles this)
- All transition buttons must have descriptive labels — do not use icon-only for destructive transitions
- "Pendiente de evaluacion" must not rely solely on italic styling — include the text, not just a dash

## Shadow Mode Gate

The `ScorePanel` component checks `useRuntimeConfig().public.scoringDisplayEnabled` (boolean, default `false`).

- When `false`: ScorePanel renders nothing (comment: `<!-- Score en modo sombra: oculto hasta calibracion -->`)
- When `true`: Full ScorePanel with score number, badge, and breakdown toggle renders

This flag is set via `NUXT_PUBLIC_SCORING_DISPLAY_ENABLED=true` in the Docker environment. No deployment required to activate — only a container restart.

> Source: CONTEXT.md D-10. Discretion: flag name and implementation pattern chosen by researcher.
