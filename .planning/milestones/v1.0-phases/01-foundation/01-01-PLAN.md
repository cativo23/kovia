  <files>
    backend/prisma.config.ts, backend/prisma/schema.prisma, backend/prisma/init.sql,
    backend/src/prisma/prisma.module.ts, backend/src/prisma/prisma.service.ts, backend/src/prisma/prisma-rls.extension.ts,

  </files>
  <action>
    1. Create `backend/prisma.config.ts` per 01-RESEARCH.md Pattern 1. Use `env('DATABASE_URL')` for the datasource URL.

    2. Create `backend/prisma/schema.prisma` with ALL Phase 1 models from 01-RESEARCH.md:
       - Enums: UserRole (ADOPTER, ORG_ADMIN, PLATFORM_ADMIN), OrgStatus (ACTIVE, DEACTIVATED)
       - Models: User, RefreshToken, Organization, OrgInvite, AuditLog
       - Use exact field definitions from 01-RESEARCH.md schema example
       - Generator outputs to `../src/generated/prisma`
       - All models use `@@map()` for snake_case table names

    3. Create `backend/prisma/init.sql` -- runs on first PostgreSQL start:
       ```sql
       -- Create app_user role (non-superuser, RLS applies)
       DO $$
       BEGIN
         IF NOT EXISTS (SELECT FROM pg_catalog.pg_roles WHERE rolname = 'app_user') THEN
           CREATE ROLE app_user LOGIN PASSWORD 'app_password';
         END IF;
       END
       $$;
       GRANT ALL PRIVILEGES ON DATABASE kovia TO app_user;
       ```

    4. Run Prisma migration via Docker:
       - `docker compose exec api npx prisma migrate dev --create-only --name init` (creates migration SQL without applying)
       - Edit the generated migration file to append RLS SQL:
         - `ALTER TABLE "users" ENABLE ROW LEVEL SECURITY;`
         - `ALTER TABLE "organizations" ENABLE ROW LEVEL SECURITY;`
         - `ALTER TABLE "org_invites" ENABLE ROW LEVEL SECURITY;`
         - `ALTER TABLE "audit_logs" ENABLE ROW LEVEL SECURITY;`
         - Grant app_user SELECT, INSERT, UPDATE, DELETE on all tables in schema public
         - Grant app_user USAGE on schema public
         - Grant app_user USAGE, SELECT on ALL SEQUENCES in schema public
         - Create tenant_isolation policies on organizations using `current_setting('app.current_org_id', true)`
         - Create admin_bypass policies for platform admin routes using `current_setting('app.is_admin', true) = 'true'`
         - Create owner_isolation policy on users (users can read their own row)
         - Create admin_full_access policy on users for admin
       - Apply migration: `docker compose exec api npx prisma migrate dev`
       - Generate client: `docker compose exec api npx prisma generate`

    5. Create PrismaService (`backend/src/prisma/prisma.service.ts`) per 01-RESEARCH.md Pattern 1:
       - Extends PrismaClient, uses PrismaPg adapter
       - Implements OnModuleInit, OnModuleDestroy

    6. Create RLS extension (`backend/src/prisma/prisma-rls.extension.ts`) per 01-RESEARCH.md Pattern 2:
       - Uses ClsService to get organizationId and isAdmin from request context
       - Wraps queries in transaction with `SET LOCAL` for tenant context
       - If isAdmin is true, sets `app.is_admin` to 'true'
       - If no org context (public routes), passes through without tenant setting

    7. Create PrismaModule (`backend/src/prisma/prisma.module.ts`):
       - Global module
       - Provides PrismaService and an RLS-extended client (using the extension factory)
       - Exports both for injection

    8. Create tenant middleware and module (`backend/src/tenant/`):
       - `tenant.middleware.ts`: Extracts org_id from JWT claims, stores in ClsService
       - `tenant.module.ts`: Registers the middleware

    9. Update `backend/src/app.module.ts` to import PrismaModule and TenantModule.

    10. Verify: Run `docker compose exec api npx prisma migrate status` to confirm migration applied. Run `docker compose exec api npx prisma db execute --stdin <<< "SELECT tablename FROM pg_tables WHERE schemaname='public';"` to verify tables exist.
