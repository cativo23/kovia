  <behavior>
    Admin service tests (backend/src/admin/admin.service.spec.ts):
    - createInvite: generates invite with token, 7-day expiry, queues invite email, logs audit "org_invited"
    - createInvite: rejects duplicate email for pending invite
    - listInvites: returns all invites with status (pending, accepted, expired)
    - resendInvite: regenerates token, resets expiry, re-queues email
    - deleteInvite: removes pending invite
    - listOrgs: returns all orgs with status and admin info
    - deactivateOrg: sets org status=DEACTIVATED, logs audit "org_deactivated"
    - reactivateOrg: sets org status=ACTIVE, logs audit "org_reactivated"
    - listUsers: returns all users (paginated) with role and status
    - deactivateUser: sets user isActive=false, logs audit "user_deactivated"
    - deleteUser: permanently deletes user + cascades, logs audit "user_deleted", requires confirmation token
    - getStats: returns total users, orgs (active/inactive), invites (pending), recent activity count

    Org service tests (backend/src/organizations/organizations.service.spec.ts):
    - acceptInvite: validates token, marks invite accepted, returns invite data
    - acceptInvite: rejects expired token (>7 days)
    - createOrg: creates org with profile fields, sets user role to ORG_ADMIN, generates slug from name
    - updateOrg: updates org profile fields (only by org admin)
    - findBySlug: returns org public profile (name, description, logo, social links)

    RLS integration tests (backend/src/prisma/rls.integration.spec.ts):
    - Two orgs created with different app_user sessions
    - Org A cannot read Org B data through RLS policy
    - Platform admin (is_admin=true) can read all orgs
    - User without tenant context gets no tenant-scoped data
